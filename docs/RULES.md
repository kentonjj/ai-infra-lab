# 学习铁律 v1（2026-10-21 起生效）

> 这四个月的目标不是「学完」，而是**留下能被别人检验的证据**。
> 每条铁律都配一个可检查的产物；做不到，就说明这周没学到，而不是「学了但忘了」。

## 0. 一条主线：输入 → 实验 → 输出 → 被质疑

只看视频、只跑 demo、只收藏论文，都不算走完一圈。一圈的定义是：

1. **输入**：读论文/源码/文档，写下 3 个问题；
2. **实验**：用最小配置验证其中 1 个问题，有对照、有数据；
3. **输出**：写成 300 字结论或一张图，别人能看懂；
4. **被质疑**：找人或找 AI 挑刺，回答不了的问题就是下一轮的输入。

## 1. 八条铁律

### 铁律 1｜先写假设，再跑实验
跑之前先在 `experiments/*/README.md` 写：我认为会发生什么、为什么。跑完只允许修改「结果」和「结论」，不许改「假设」。
**防止**：跑完盯着数字编故事。
**验收**：git 记录里，假设那段早于 `run.sh` 的最后修改。

### 铁律 2｜无对照，不结论
一次只改一个变量，必须有基线；单次结果只能叫「观察」，不能叫「结论」。有波动就重复 3 次或说明为什么不重复。
**防止**：「感觉快了」「好像有效」。
**验收**：结果表里有 control 列，且写了波动范围。
**采样**：服务级压测每档 ≥200 请求 + 20 预热；p99 最好 500–1000 个样本——n=200 时 p99 只有约 3 个样本，只能标「仅供参考」，主看 p95 与 max。

### 铁律 3｜性能数字六件套
模型与量化、引擎版本、输入/输出长度、并发或 QPS、GPU 型号与显存、关键启动参数。**缺一项，数据作废。**
**防止**：无法复现，面试被追问两句就穿。
**验收**：每份报告顶部都有这张表。

### 铁律 4｜源码三问
说「我读过某模块」之前，必须答得出：入口函数/文件在哪、核心数据结构是什么、异常和边界怎么走。
**防止**：把「看过」当成「读懂」。
**验收**：笔记里有三个答案 + 行号；每两周随机抽查一次。

### 铁律 5｜72 小时输出律
任何新知识（论文、源码、课程）在 72 小时内必须变成一次输出：一段笔记、一个实验、一次讲解。超时没输出，就当作没学，重新来。
**防止**：收藏夹式学习，输入很多、留存为零。
**验收**：笔记日期 ≤ 输入日期 + 3 天。

### 铁律 6｜AI 验证门
AI 给的代码必须跑过测试或一次真实请求；AI 给的结论必须找到出处（源码/论文/自己的数据）；不确定的 API 先查对应版本文档。
**防止**：把生成物当成自己的知识。
**验收**：commit 标 `verified` / `unverified`；`docs/ai-log.md` 写清它错在哪。

### 铁律 7｜每周一个可复现交付
周日前必须有一个「陌生人按 README 能跑出来」的东西：脚本、图、报告、能起服务的配置。没有交付，这周不算完成——**下周不加新内容，先补账**。
**防止**：用「看了很多」替代「做出来」。
**验收**：周复盘里贴出复现命令和结果。

### 铁律 8｜失败日志
每周至少记 1 个失败：假设被推翻、OOM、数据对不上、方案回滚。写清根因、修复、下次怎么提前发现。
**防止**：只留成功路径，一被追问就露馅。
**验收**：`docs/failures.md` 每周一条。

## 2. 四条红线（碰了就停）

- 不把「跑通 demo」写成「掌握」。
- 不用单次运行、单卡单并发的结果下结论。
- 不在没有基线的时候做优化。
- 不把没跑过的数字写进简历或复盘。
- 不硬耗：同一个报错卡满 90 分钟，必须写下现状、换一条路（查文档/问人/降级），不许用战术勤奋掩盖卡点。

## 3. 每周日 10 分钟审计（5 个 yes/no）

1. 本周有没有一个别人能复现的交付？
2. 有没有一组带对照的数据？
3. 有没有一条「我原来想错了」的记录？
4. 有没有一个概念能 3 分钟讲清、不用术语？
5. 下周的实验假设写了吗？

**≥2 个 no：下周不加新内容，先补上。** 这 5 问已经做进计划网站首页（WEEKLY · 5 问），每周日高亮，点完自动算结论。
每月最后一周额外问一句：这个月砍掉哪个方向/工具？（只能留一条主线）

## 4. 如果只能守三条

1. **铁律 2（对照实验）**——决定你是在做工程还是在做演示。
2. **铁律 3（六件套）**——决定你的数据能不能被别人相信。
3. **铁律 5（72 小时输出）**——决定四个月后你还记得多少。

> 这三条守住，其他做不到也不会太差；这三条守不住，计划表打得再满也是自我感动。
